# 数据库设计规范

## 1. 概述

### 1.1 数据库选型
- **主数据库**: MySQL 8.0+
- **缓存数据库**: Redis 6.0+
- **数据仓库**: MySQL 8.0+ (分析型查询)

### 1.2 命名规范

| 对象类型 | 命名规则 | 示例 |
|---------|---------|------|
| 表名 | 小写，下划线分隔，复数形式 | `users`, `user_sessions` |
| 字段名 | 小写，下划线分隔 | `user_name`, `created_at` |
| 主键索引 | `pk_表名` | `pk_users` |
| 唯一索引 | `uk_字段名` | `uk_phone` |
| 普通索引 | `idx_字段名` | `idx_status` |
| 联合索引 | `idx_字段1_字段2` | `idx_user_id_created_at` |
| 外键名 | `fk_从表_主表` | `fk_user_oauth_bindings_users` |

### 1.3 通用字段

所有业务表必须包含以下字段：

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `id` | BIGINT UNSIGNED | AUTO_INCREMENT | 主键，自增 |
| `created_at` | DATETIME | CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

### 1.4 字段类型规范

| 数据类型 | 使用场景 | 示例 |
|---------|---------|------|
| `BIGINT UNSIGNED` | 主键ID、外键ID | `id`, `user_id` |
| `VARCHAR(n)` | 变长字符串 | `user_name`, `email` |
| `CHAR(n)` | 定长字符串 | 固定长度的编码 |
| `TINYINT` | 小整数值（状态、类型） | `status`, `gender` |
| `INT` | 普通整数值 | `age`, `count` |
| `BIGINT` | 大整数值（时间戳） | `timestamp` |
| `DECIMAL(m,d)` | 精确小数（金额） | `amount DECIMAL(10,2)` |
| `DATETIME` | 日期时间 | `created_at` |
| `DATE` | 日期 | `birthday` |
| `TEXT` | 长文本 | `content`, `json_data` |
| `JSON` | JSON数据（MySQL 5.7+） | `properties` |

### 1.5 索引设计原则

1. **主键索引**：所有表必须有主键，使用自增ID
2. **唯一索引**：业务唯一性约束字段
3. **普通索引**：频繁查询的WHERE条件字段
4. **联合索引**：多字段查询场景，遵循最左前缀原则
5. **索引数量**：单表索引不超过5个，避免过多索引影响写入性能

### 1.6 分区分表策略

| 表类型 | 分区策略 | 说明 |
|--------|---------|------|
| 日志表 | 按时间RANGE分区 | 按天或按月分区 |
| 大表 | 按ID HASH分区 | 分散数据压力 |
| 历史表 | 定期归档 | 保留固定时间后迁移 |

### 1.7 数据归档策略

| 数据类型 | 归档策略 | 保留时长 |
|---------|---------|---------|
| 操作日志 | 按时间归档到历史库 | 180天 |
| 会话历史 | 定期清理过期数据 | 180天 |
| 临时数据 | 定期清理 | 7天 |
