## 2. 多设备会话管理

### 2.1 Session 数据结构

```typescript
interface Session {
  id: string;              // 会话唯一标识
  user_id: string;         // 用户 ID
  device_id: string;       // 设备指纹
  device_name: string;     // 设备名称
  device_type: 'web' | 'ios' | 'android' | 'desktop';
  ip_address: string;      // 登录 IP
  location: string;        // 登录地点
  user_agent: string;      // User-Agent
  access_token: string;    // Access Token
  refresh_token: string;   // Refresh Token
  status: 'active' | 'terminated' | 'expired';
  created_at: Date;        // 创建时间
  expires_at: Date;        // 过期时间
}
```

### 2.2 WebSocket 通信协议

**连接建立（客户端发送）**：
```json
{
  "type": "auth",
  "token": "access_token"
}
```

**服务端推送消息**：
```json
{
  "type": "SESSION_TERMINATED",
  "data": {
    "session_id": "xxx",
    "terminated_by": "user",
    "terminated_at": "2024-03-04T10:30:00Z"
  }
}
```

**消息类型**：

| type | 说明 | 触发场景 |
|------|------|----------|
| `SESSION_TERMINATED` | 会话被终止 | 用户主动登出某设备 |
| `PASSWORD_CHANGED` | 密码已修改 | 用户修改密码 |
| `PROFILE_UPDATED` | 资料已更新 | 用户修改个人资料 |
| `NEW_LOGIN` | 新设备登录 | 其他设备登录 |

**WebSocket 连接地址**：`WS /ws/sessions`


## 3. 跨端实现方案

### 3.1 各端差异对比

| 平台 | Token 存储 | 登录触发方式 | 状态同步 | 特殊限制 |
|------|-----------|-------------|---------|---------|
| **Web** | Cookie | 页面跳转/二维码 | WebSocket/SSE | 跨域限制、第三方Cookie限制 |
| **iOS** | Keychain | ASWebAuthenticationSession | Push/APNs | 无法共享系统浏览器Cookie |
| **Android** | EncryptedSharedPreferences | Chrome Custom Tabs | Push/FCM | Root设备需降级信任 |
| **小程序** | wx.setStorage | web-view/按钮 | 轮询/WebSocket | 无法直接唤起App |

### 3.2 存储方案

| 平台 | 推荐方案 | 注意点 |
|------|---------|--------|
| iOS | Keychain | 卸载后数据仍保留，需考虑清理策略 |
| Android | EncryptedSharedPreferences + Keystore | Root设备需检测并降级信任等级 |
| 小程序 | Storage | 受限于容器，退出小程序后需重新校验 |

### 3.3 浏览器选择（App 内登录）

| 方案 | 优点 | 缺点 | 推荐场景 |
|------|------|------|---------|
| ASWebAuthenticationSession | iOS专用登录会话，安全 | iOS 12+ | **iOS首选** |
| Chrome Custom Tabs | 共享Chrome Cookie，安全 | 需安装Chrome | **Android首选** |
| 系统浏览器 | 可能已登录 | 跳转体验差 | 备用方案 |
| 应用内WebView | 体验可控 | 无法共享系统Cookie | 不推荐 |

### 3.4 移动端请求签名

```kotlin
// 每个请求附加签名（防重放攻击）
fun signRequest(request: Request, appSecret: String): Request {
    val timestamp = System.currentTimeMillis()
    val nonce = generateNonce()
    val sign = sha256("${appId}${timestamp}${nonce}${appSecret}")

    return request.newBuilder()
        .addHeader("X-App-ID", appId)
        .addHeader("X-Timestamp", timestamp.toString())
        .addHeader("X-Nonce", nonce)
        .addHeader("X-Sign", sign)
        .build()
}
```

### 3.5 Token 自动刷新（SDK 实现）

```typescript
class SSOClient {
  async requestWithToken(apiRequest) {
    if (this.isTokenExpiringSoon()) {
      await this.refreshTokenSilently();
    }
    return this.executeRequest(apiRequest);
  }

  private async refreshTokenSilently() {
    try {
      const newToken = await this.callRefreshAPI();
      this.saveToken(newToken);
    } catch (e) {
      this.redirectToLogin();
    }
  }
}
```

### 3.6 单点登出同步（移动端）

```java
// Android: 接收登出推送
class PushReceiver extends FirebaseMessagingService() {
  override fun onMessageReceived(message: RemoteMessage) {
    if (message.data["type"] == "USER_LOGOUT") {
      clearLocalToken();
      redirectToLogin();
    }
  }
}
```

### 3.8 小程序特殊限制

| 限制 | 解决方案 |
|------|---------|
| 无法直接唤起App | 使用 `<button open-type="launchApp">` 或引导用户手动打开 |
| 无法读写Cookie | 通过 Storage 存储，请求时手动添加 Header |
| 后台刷新问题 | 每次启动/回到前台时主动校验Token |
| web-view限制 | 需配置业务域名白名单 |

### 3.9 跨端登录方案对比

| 方案 | 场景 | 优点 | 缺点 |
|------|------|------|------|
| **二维码登录** | Web←→App | 最安全，无需输入密码 | 需要扫码操作 |
| **短信验证码** | 全平台通用 | 简单直接 | 短信成本，可能被拦截 |
| **推送授权** | App→Web | 一键确认，体验好 | 依赖推送通道 |
| **URL Scheme** | App↔小程序 | 无缝跳转 | 小程序无法主动唤起App |
