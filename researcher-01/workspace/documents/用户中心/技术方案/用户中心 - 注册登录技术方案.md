## 3. 注册流程

### 3.1 手机号注册

```
用户输入手机号
         ↓
发送短信验证码 ─────────────────────────────┐
         ↓                                  │
Redis 存储验证码 (key: sms:{phone})         │
TTL: 5分钟                                  │
         ↓                                  │
用户输入验证码 ←────────────────────────────┘
         ↓
验证验证码
         ↓
验证通过?
   /        \
 否          是
  ↓            ↓
返回错误    检查手机号是否已注册
               ↓
         已注册?
          /        \
        是          否
         ↓            ↓
    返回错误    创建用户记录
                    ↓
              生成 Token 对
                    ↓
              创建 Session
                    ↓
              返回登录成功
```

**业务规则**：
1. 验证码 5 分钟内有效，错误 3 次后需重新获取
2. 同一手机号 1 分钟内只能发送 1 次验证码
3. 同一手机号 1 小时内最多发送 5 次验证码
4. 同一 IP 1 小时内最多注册 10 个账户


### 3.2 邮箱注册

```
用户输入邮箱、密码
         ↓
校验邮箱格式
         ↓
校验密码强度
         ↓
检查邮箱是否已注册
         ↓
创建用户记录 (status: 未激活)
         ↓
发送激活邮件 ──────────────────────────────┐
         ↓                                  │
Redis 存储激活令牌                          │
(key: email_verify:{token})                 │
TTL: 24小时                                │
         ↓                                  │
用户点击激活链接 ←──────────────────────────┘
         ↓
验证激活令牌
         ↓
激活用户账户 (status: 启用)
         ↓
自动登录 (生成 Token)
```

**密码强度要求**：
- 最少 8 位字符
- 包含大小写字母
- 包含数字
- 可包含特殊字符 `!@#$%^&*`


### 3.3 第三方登录注册

```
用户点击第三方登录按钮
         ↓
重定向到第三方授权页面
         ↓
用户授权
         ↓
第三方回调 (携带 authorization_code)
         ↓
用 code 换取 access_token 和用户信息
         ↓
根据 provider + provider_user_id 查询绑定关系
         ↓
已绑定?
   /        \
 是          否
  ↓            ↓
直接登录    检查用户信息中的手机号/邮箱
               ↓
         已存在?
          /        \
        是          否
         ↓            ↓
    绑定并登录   创建新用户并绑定
```


## 4. 登录流程

### 4.1 密码登录

```
用户输入账号(手机/邮箱/用户名) + 密码
         ↓
查询用户
         ↓
用户存在?
   /        \
 否          是
  ↓            ↓
记录失败日志   bcrypt 比对密码
(不提示具体    ↓
 错误类型)   密码正确?
               /        \
             否          是
              ↓            ↓
        记录失败日志   清除失败次数
        失败次数+1      ↓
        ↓            生成 Token 对
        失败>=5?       创建 Session
          /        \    ↓
        是          否  返回登录成功
         ↓            ↓
    锁定账户30分钟
```

**安全规则**：
1. 连续失败 5 次，锁定账户 30 分钟
2. 连续失败 10 次，锁定账户 24 小时
3. 登录成功后清除失败次数记录


### 4.2 验证码登录

```
用户输入手机号
         ↓
发送短信验证码
         ↓
用户输入验证码
         ↓
验证验证码
         ↓
验证通过?
   /        \
 否          是
  ↓            ↓
返回错误    用户存在?
               /        \
             否          是
              ↓            ↓
        创建新用户     直接登录
               ↓            ↓
            生成 Token    生成 Token
               ↓            ↓
            创建 Session  创建 Session
               ↓            ↓
            返回成功      返回成功
```

**注意**：验证码登录支持"一键注册"，即手机号未注册时自动创建账户。


## 5. Token 机制

### 5.1 双 Token 架构

```
┌─────────────────┐         ┌─────────────────┐
│   Access Token  │         │  Refresh Token  │
│   (访问令牌)     │         │   (刷新令牌)     │
├─────────────────┤         ├─────────────────┤
│ 类型: JWT       │         │ 类型: UUID      │
│ 有效期: 2小时   │         │ 有效期: 7天     │
│ 存储: 客户端    │         │ 存储: Redis     │
│ 验证: 本地验签  │         │ 验证: 查 Redis  │
│ 吊销: 不可吊销  │         │ 吊销: 可删除    │
└─────────────────┘         └─────────────────┘
         │                            │
         └────────────┬───────────────┘
                      │
                      ▼
              ┌───────────────┐
              │   Token 刷新   │
              │  Access过期后  │
              │ 用Refresh换取  │
              │ 新的Token对    │
              └───────────────┘
```


### 5.2 Access Token (JWT)

**Payload 结构**：
```json
{
  "iss": "user-center",
  "sub": "user_12345",
  "aud": "app_web",
  "exp": 1710931200,
  "iat": 1710924000,
  "jti": "jwt_abc123",
  "device_id": "fp_xyz789",
  "session_id": "sess_001"
}
```

**字段说明**：
| 字段 | 说明 |
|------|------|
| iss | 签发者 |
| sub | 用户ID |
| aud | 应用ID |
| exp | 过期时间戳 |
| iat | 签发时间戳 |
| jti | Token唯一标识 |
| device_id | 设备指纹 |
| session_id | 会话ID |

**签名算法**：RS256 (RSA + SHA-256)


### 5.3 Refresh Token

**格式**：`rt_{32位随机字符串}`

**Redis 存储**：
```
Key: refresh:rt_a3f8b2c1...
Value: {
  "user_id": "user_12345",
  "session_id": "sess_001",
  "device_id": "fp_xyz789",
  "created_at": 1710924000,
  "expires_at": 1711528800
}
TTL: 7天
```


### 5.4 Token 刷新流程

```
客户端请求 (携带过期 Access Token)
         ↓
服务端验证 Access Token 过期
         ↓
返回 401 Token过期
         ↓
客户端使用 Refresh Token 请求 /refresh
         ↓
服务端验证 Refresh Token
   - 查 Redis 是否存在
   - 是否过期
   - 是否被吊销
         ↓
验证通过?
   /        \
 否          是
  ↓            ↓
返回 401    生成新的 Access Token
               ↓
            生成新的 Refresh Token
               ↓
            删除旧 Refresh Token
               ↓
            存储新 Refresh Token
               ↓
            返回新的 Token 对
```

**刷新策略**：
- Refresh Token 只能使用一次（轮换机制）
- 新的 Refresh Token 有效期重新计算 7 天
- 旧 Refresh Token 保留 5 分钟（优雅过渡）


## 6. 验证码系统

### 6.1 短信验证码

**发送规则**：
| 限制类型 | 阈值 | 时间窗口 | 行为 |
|----------|------|----------|------|
| 同一手机号 | 1次 | 1分钟 | 限制发送 |
| 同一手机号 | 5次 | 1小时 | 限制发送 |
| 同一手机号 | 10次 | 1天 | 限制发送 |
| 同一IP | 20次 | 1小时 | 限制发送 |

**Redis 存储**：
```
Key: sms:{phone}
Value: {验证码}
TTL: 5分钟

Key: sms_limit:{phone}
Value: {发送次数}
TTL: 1小时
```

**验证规则**：
1. 验证码 5 分钟内有效
2. 连续错误 3 次，验证码失效
3. 验证码验证成功后立即删除


### 6.2 邮箱验证码

与短信验证码类似，TTL 为 10 分钟。


### 6.3 图形验证码

**使用场景**：
- 注册频率过高
- 登录失败次数过多
- 疑似机器人操作

**Redis 存储**：
```
Key: captcha:{uuid}
Value: {验证码}
TTL: 5分钟
```


## 7. 安全机制

### 7.1 密码安全

**加密算法**：bcrypt
- 成本因子：12
- 自动加盐
- 单向哈希，无法反解

**密码策略**：
```typescript
function validatePassword(password: string): boolean {
  // 最少8位
  if (password.length < 8) return false;
  
  // 包含大写字母
  if (!/[A-Z]/.test(password)) return false;
  
  // 包含小写字母
  if (!/[a-z]/.test(password)) return false;
  
  // 包含数字
  if (!/[0-9]/.test(password)) return false;
  
  return true;
}
```


### 7.2 防刷机制

**注册防刷**：
| 维度 | 阈值 | 时间窗口 | 处罚 |
|------|------|----------|------|
| 同一IP | 10次 | 1小时 | 图形验证码 |
| 同一IP | 20次 | 1小时 | 拒绝服务 |
| 同一设备 | 5次 | 1小时 | 图形验证码 |

**登录防刷**：
| 维度 | 阈值 | 时间窗口 | 处罚 |
|------|------|----------|------|
| 同一账号 | 5次 | 30分钟 | 锁定账户 |
| 同一IP | 20次 | 15分钟 | 图形验证码 |
| 同一设备 | 10次 | 15分钟 | 图形验证码 |


### 7.3 限流配置

**Nginx 层限流**：
```nginx
# 注册接口限流
limit_req_zone $binary_remote_addr zone=register:10m rate=5r/m;

# 登录接口限流
limit_req_zone $binary_remote_addr zone=login:10m rate=10r/m;

# 验证码接口限流
limit_req_zone $binary_remote_addr zone=sms:10m rate=1r/m;
```

**应用层限流**：
```java
@RateLimiter(name = "register", limit = 5, period = 60)
public Result register(RegisterRequest request) {
    // 注册逻辑
}
```


### 7.4 安全审计

**审计日志内容**：
```json
{
  "event_type": "LOGIN_ATTEMPT",
  "user_id": "user_12345",
  "ip_address": "192.168.1.100",
  "user_agent": "Mozilla/5.0...",
  "device_id": "fp_xyz789",
  "timestamp": "2024-03-23T10:30:00Z",
  "status": "SUCCESS|FAILED",
  "fail_reason": "INVALID_PASSWORD",
  "request_id": "req_abc123"
}
```

**事件类型**：
- USER_REGISTER: 用户注册
- LOGIN_ATTEMPT: 登录尝试
- LOGIN_SUCCESS: 登录成功
- LOGIN_FAILED: 登录失败
- ACCOUNT_LOCKED: 账户锁定
- PASSWORD_CHANGED: 密码修改
- TOKEN_REFRESHED: Token刷新
- LOGOUT: 登出

## 9. 性能优化

### 9.1 数据库优化

**索引优化**：
- users.phone: 唯一索引
- users.email: 唯一索引
- users.user_name: 唯一索引
- user_sessions.user_id: 普通索引
- user_sessions.session_id: 唯一索引

**读写分离**：
- 读操作：从库查询
- 写操作：主库写入


### 9.2 缓存策略

**Redis 缓存**：
- 用户信息缓存：TTL 1小时
- 验证码缓存：TTL 5分钟
- Token黑名单：TTL 2小时

**本地缓存**（Caffeine）：
- 用户基础信息：最大 10000 条，TTL 10分钟
- Token公钥：TTL 1天


### 9.3 异步处理

**异步任务**（消息队列）：
- 发送短信/邮件
- 记录审计日志
- 更新用户最后登录时间
