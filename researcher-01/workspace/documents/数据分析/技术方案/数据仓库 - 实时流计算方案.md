# 实时流计算（Flink）

## 设计原则

1. **简单优先**: 能用 Logstash 解决的不用 Flink
2. **分层清晰**: ODS → DWD → DWS → ADS 职责分离
3. **成本可控**: 优先使用现有组件，避免过度设计

## 架构概览

```
┌──────────────────────────────────────────────────────────────┐
│                     数据流架构                                │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│   实时链路 (Logstash 直写)          离线链路 (Flink 批处理)    │
│   ━━━━━━━━━━━━━━━━━━━━━━━━          ━━━━━━━━━━━━━━━━━━━━━━   │
│                                                              │
│   ┌──────────┐                       ┌──────────────┐       │
│   │ Nginx    │──→ Filebeat ──→      │ MySQL ODS    │       │
│   │ 网关日志  │    Logstash ──→      │ (原始数据)    │       │
│   └──────────┘    ┌─────────┐        └──────┬───────┘       │
│                   │  Redis  │               │               │
│                   │ (PV/UV) │    Flink 批处理 │               │
│                   └─────────┘        ↓       ↓               │
│                         ↓       ┌──────────┐                │
│                   ┌──────────┐  │ DWD/DWS  │                │
│                   │ 实时看板  │←─┤ 明细/汇总 │                │
│                   └──────────┘  └────┬─────┘                │
│                                      ↓                       │
│                                 ┌──────────┐                │
│                                 │   ADS    │                │
│                                 │ (报表缓存)│                │
│                                 └──────────┘                │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 为什么不用 Flink 做实时？

| 对比项 | Logstash 直写 | Flink 实时流 |
|--------|--------------|-------------|
| 复杂度 | 低 | 高 |
| 资源占用 | 低（~512MB） | 高（~2GB+） |
| 运维成本 | 低 | 高 |
| 延迟 | 秒级（可接受） | 亚秒级 |
| 适用场景 | 简单计数（PV/UV） | 复杂窗口计算 |

**结论**: 当前场景 Logstash 完全够用，无需引入 Flink 实时链路

# 实时看板

## 需求描述

提供实时数据看板，展示关键指标的实时变化趋势。

## 实时指标（Logstash 直写 Redis）

| 指标 | 写入方式 | 更新频率 |
|------|---------|---------|
| 实时 PV | Logstash → Redis HyperLogLog | 每条事件 |
| 实时 UV | Logstash → Redis HyperLogLog | 每条事件 |
| 在线人数 | Logstash → Redis Set（TTL 30分钟）| 每条事件 |
| 事件计数 | Logstash → Redis String INCR | 每条事件 |

## 技术方案

实时指标由 Logstash Pipeline 在写入 ODS 的同时更新 Redis，前端轮询 Redis 获取实时数据，无需 Flink 参与实时链路。


数据清洗说明

DWD层数据从ODS层清洗而来，主要处理逻辑：

```sql
-- 从ODS清洗到DWD示例：提取用户活跃明细
INSERT INTO dwd_user_active_daily
SELECT
    user_id,
    DATE(event_time) as active_date,
    MIN(DATE(event_time)) OVER (PARTITION BY user_id) as first_login_date,
    channel as register_channel,
    platform as first_platform,
    app_version as first_app_version,
    COUNT(*) as login_count,
    DATEDIFF(DATE(event_time), MIN(DATE(event_time)) OVER (PARTITION BY user_id)) as user_age_days,
    dt
FROM ods_tracking_event_raw
WHERE event_name = 'user_login'
  AND user_id IS NOT NULL
GROUP BY user_id, DATE(event_time), dt;
```

## 6. ETL 计算流程

### 7.1 每日计算时序

```
01:00 - ODS → DWD
        清洗埋点事件，生成用户活跃明细

02:00 - DWD → DWS轻度汇总
        汇总新增用户

03:00 - DWS留存计算
        计算新用户留存率

04:00 - DWS → ADS
        生成报表缓存、同期群分析
```

### 7.2 核心计算逻辑

```sql
-- Step 1: 新用户留存率计算（基于 user_id 和 first_login_date）
INSERT INTO dws_new_user_retention
SELECT
  first_login_date,
  'ALL', 'ALL',
  COUNT(DISTINCT user_id) as new_users,
  COUNT(DISTINCT CASE WHEN user_age_days = 1 THEN user_id END) as d1_retained,
  COUNT(DISTINCT CASE WHEN user_age_days = 7 THEN user_id END) as d7_retained,
  COUNT(DISTINCT CASE WHEN user_age_days = 30 THEN user_id END) as d30_retained,
  -- 留存率计算
  COUNT(DISTINCT CASE WHEN user_age_days = 1 THEN user_id END) * 100.0 / COUNT(DISTINCT user_id) as d1_rate,
  COUNT(DISTINCT CASE WHEN user_age_days = 7 THEN user_id END) * 100.0 / COUNT(DISTINCT user_id) as d7_rate,
  COUNT(DISTINCT CASE WHEN user_age_days = 30 THEN user_id END) * 100.0 / COUNT(DISTINCT user_id) as d30_rate
FROM dwd_user_active_daily
WHERE first_login_date = '${biz_date}'
GROUP BY first_login_date;

-- 注意：新用户留存计算用户在 T+N 日有再次登录行为即算留存
-- 新用户留存：用户在 T+N 日再次登录即算留存
INSERT INTO dws_new_user_retention
SELECT
  r.first_login_date,
  'ALL', 'ALL',
  COUNT(DISTINCT r.user_id) as new_users,
  COUNT(DISTINCT CASE WHEN DATEDIFF(a.active_date, r.first_login_date) = 1 THEN r.user_id END) as d1_retained,
  COUNT(DISTINCT CASE WHEN DATEDIFF(a.active_date, r.first_login_date) = 7 THEN r.user_id END) as d7_retained,
  COUNT(DISTINCT CASE WHEN DATEDIFF(a.active_date, r.first_login_date) = 30 THEN r.user_id END) as d30_retained,
  -- 留存率计算
  COUNT(DISTINCT CASE WHEN DATEDIFF(a.active_date, r.first_login_date) = 1 THEN r.user_id END) * 100.0 / COUNT(DISTINCT r.user_id) as d1_rate,
  COUNT(DISTINCT CASE WHEN DATEDIFF(a.active_date, r.first_login_date) = 7 THEN r.user_id END) * 100.0 / COUNT(DISTINCT r.user_id) as d7_rate,
  COUNT(DISTINCT CASE WHEN DATEDIFF(a.active_date, r.first_login_date) = 30 THEN r.user_id END) * 100.0 / COUNT(DISTINCT r.user_id) as d30_rate
FROM ods_user_register_raw r
LEFT JOIN dwd_user_active_daily a ON r.user_id = a.user_id
  AND a.active_date > r.first_login_date
WHERE r.first_login_date = '${biz_date}'
GROUP BY r.first_login_date;
```

## 8. SQL 查询示例

### 8.1 页面PV/UV查询

```sql
-- 查询某日各页面PV/UV
SELECT
    page_path,
    SUM(pv_count) as total_pv,
    SUM(uv_count) as total_uv,
    AVG(avg_duration) as avg_stay_ms
FROM dws_page_view_dm
WHERE stat_date = '2024-03-12'
GROUP BY page_path
ORDER BY total_pv DESC;
```

### 8.2 漏斗分析查询

```sql
-- 查询某日注册转化漏斗
SELECT
    funnel_name,
    steps_config,
    step1_users,
    step2_users,
    step3_users,
    overall_conversion
FROM dws_funnel_stats_dm
WHERE funnel_id = 'register_funnel'
  AND stat_date = '2024-03-12'
  AND platform = 'all';
```

### 8.3 事件明细查询

```sql
-- 查询某用户的页面浏览历史
SELECT
    event_name,
    page_path,
    event_time,
    properties
FROM dwd_tracking_event_di
WHERE user_id = 123456
  AND event_type = 'page_view'
  AND dt >= '2024-03-01'
ORDER BY event_time DESC
LIMIT 100;
```
