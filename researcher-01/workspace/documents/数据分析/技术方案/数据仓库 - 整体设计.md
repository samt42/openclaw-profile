# 数据仓库设计文档

## 1. 概述

### 1.1 设计目标

构建统一的数据仓库平台，支持：
- 数据采集与集成（CDC、日志、埋点）
- 数据分层存储（ODS/DWD/DWS/ADS）
- 数据分析与报表
- 用户画像与标签体系

### 1.3 分层说明

| 分层 | 全称 | 说明 | 数据保留策略 |
|------|------|------|-------------|
| ODS | Operational Data Store | 原始数据，与数据源保持一致 | 7-30天 |
| DWD | Data Warehouse Detail | 清洗后的明细数据，统一格式 | 90天-1年 |
| DWS | Data Warehouse Service | 轻度汇总，按维度聚合 | 2年 |
| ADS | Application Data Service | 应用数据，直接面向报表/API | 90天 |

## 5. 关键技术决策

### 5.1 存储层选型

| 方案 | 成本(月) | 适用场景 | 推荐度 |
|------|---------|---------|--------|
| MySQL 分区表 | ~500元 | DAU < 5万，预算优先 | ⭐⭐⭐⭐⭐ |
| MySQL + ClickHouse | ~1000元 | DAU 5-20万，需复杂分析 | ⭐⭐⭐⭐ |
| 云原生数仓 | ~1500元 | 无运维团队，预算充足 | ⭐⭐⭐ |

**当前推荐**: MySQL 分区表方案（DAU 2万规模完全够用）

### 5.2 实时计算选型

| 方案 | 适用场景 | 推荐度 |
|------|---------|--------|
| Logstash 直写 Redis | 实时PV/UV/在线人数 | ⭐⭐⭐⭐⭐ 推荐 |
| Flink 批处理 | T+1 离线计算（留存/漏斗） | ⭐⭐⭐⭐ 推荐 |
| Flink 实时流 | 复杂实时场景（当前不需要） | ⭐⭐⭐ |

### 5.3 CDC 工具选型

| 工具 | 特点 | 推荐 |
|------|------|------|
| Canal | 国产成熟，社区活跃 | ⭐⭐⭐⭐⭐ 推荐 |
| Debezium | 功能丰富，文档完善 | ⭐⭐⭐⭐ |

## 6. 实施路线图

```
Phase 1: 基础设施 (2周)
├── Week 1: Nginx网关 + Filebeat部署
└── Week 2: Logstash + MySQL ODS + Redis

Phase 2: 数据接入 (2周)
├── Week 3: 埋点SDK接入 + 业务库CDC
└── Week 4: 数据清洗链路验证

Phase 3: 分层建设 (2周)
├── Week 5: ODS → DWD ETL开发
└── Week 6: DWD → DWS 汇总计算

Phase 4: 应用层 (2周)
├── Week 7: 留存率计算 + 报表API
└── Week 8: 实时看板 + BI接入

Phase 5: 优化治理 (1周)
├── Week 9: 监控告警 + 性能优化
└── Week 10: 文档完善 + 培训
```

## 7. 风险与应对

| 风险 | 可能性 | 影响 | 应对策略 |
|------|--------|------|---------|
| MySQL性能瓶颈 | 中 | 高 | 预留ClickHouse升级路径 |
| 数据质量问题 | 高 | 高 | 核心指标对账监控 |
| ETL任务失败 | 中 | 高 | 失败重试 + 告警通知 |
| 日志磁盘满 | 高 | 中 | 7天轮转 + 磁盘监控 |
