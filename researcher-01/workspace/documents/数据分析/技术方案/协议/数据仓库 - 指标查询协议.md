## 1. 协议定义

本文档定义数据分析相关的数据查询 API 接口规范。所有分析查询统一通过通用聚合接口发起：

```http
POST /analytics
Content-Type: application/json
```

**请求体结构**:

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| business | string | 是 | 业务域，见各节说明 |
| timeRange.startTime | string | 是 | 开始时间，格式 `YYYY-MM-DD HH:mm:ss` |
| timeRange.endTime | string | 是 | 结束时间，格式 `YYYY-MM-DD HH:mm:ss` |
| granularity | string | 是 | 时间粒度：`hour` / `day` / `week` / `month` / `total` |
| dimensions | array\<string\> | 否 | 分组维度字段列表，为空则不分组 |
| metrics | array\<object\> | 是 | 指标定义列表，至少一个 |
| metrics[].field | string | 是 | 指标字段名 |
| metrics[].aggregation | string | 是 | 聚合函数：`summary` / `count` / `distinct_count` / `avg` / `max` / `min` |
| metrics[].alias | string | 否 | 响应中该指标的别名 |
| filters | array\<object\> | 否 | 过滤条件列表，多个条件取 AND |
| filters[].field | string | 是 | 过滤字段名 |
| filters[].operator | string | 是 | 操作符：`=` / `!=` / `>` / `>=` / `<` / `<=` / `in` / `not_in` / `between` |
| filters[].value | any | 是 | 过滤值，`in` / `not_in` 时为数组，`between` 时为 `[min, max]` |

## 2. 示例

### 2.1 留存趋势查询

`business = "retention"`，按天统计新用户次日留存率：

```json
{
    "business": "retention",
    "timeRange": {
        "startTime": "2026-03-01 00:00:00",
        "endTime": "2026-03-07 23:59:59"
    },
    "granularity": "day",
    "metrics": [
        {"field": "new_count", "aggregation": "summary"},
        {"field": "retained_count", "aggregation": "summary"},
        {"field": "retention_rate", "aggregation": "avg"}
    ],
    "filters": [
        {"field": "retention_type", "operator": "=", "value": "new_user"},
        {"field": "period", "operator": "=", "value": "d1"}
    ]
}
```

**响应示例**:
```json
{
    "code": 0,
    "message": "success",
    "data": {
        "business": "retention",
        "granularity": "day",
        "rows": [
            {"date": "2026-03-01", "new_count": 1000, "retained_count": 350, "retention_rate": 35.0},
            {"date": "2026-03-02", "new_count": 1200, "retained_count": 456, "retention_rate": 38.0}
        ],
        "total": 7
    }
}
```

### 2.2 留存对比分析

按渠道对比七日留存，汇总全区间（`granularity = "total"`）：

```json
{
    "business": "retention",
    "timeRange": {
        "startTime": "2026-03-01 00:00:00",
        "endTime": "2026-03-07 23:59:59"
    },
    "granularity": "total",
    "dimensions": ["channel"],
    "metrics": [
        {"field": "new_users", "aggregation": "summary"},
        {"field": "retention_rate", "aggregation": "avg"}
    ],
    "filters": [
        {"field": "retention_type", "operator": "=", "value": "new_user"},
        {"field": "period", "operator": "=", "value": "d7"}
    ]
}
```

**响应示例**:
```json
{
    "code": 0,
    "message": "success",
    "data": {
        "business": "retention",
        "granularity": "total",
        "dimensions": ["channel"],
        "rows": [
            {"channel": "AppStore", "new_users": 500, "retention_rate": 42.0},
            {"channel": "华为应用市场", "new_users": 300, "retention_rate": 38.5}
        ],
        "total": 2
    }
}
```

### 2.3 同期群分析

`business = "retention_cohort"`，按注册日期分组，输出各留存周期留存率：

```json
{
    "business": "retention_cohort",
    "timeRange": {
        "startTime": "2026-03-01 00:00:00",
        "endTime": "2026-03-07 23:59:59"
    },
    "granularity": "day",
    "metrics": [
        {"field": "cohort_size", "aggregation": "summary"},
        {"field": "d1_rate", "aggregation": "avg"},
        {"field": "d7_rate", "aggregation": "avg"},
        {"field": "d30_rate", "aggregation": "avg"}
    ],
    "filters": [
        {"field": "retention_type", "operator": "=", "value": "new_user"}
    ]
}
```

**响应示例**:
```json
{
    "code": 0,
    "message": "success",
    "data": {
        "business": "retention_cohort",
        "granularity": "day",
        "rows": [
            {"date": "2026-03-01", "cohort_size": 1000, "d1_rate": 35.0, "d7_rate": 30.0, "d30_rate": 25.0},
            {"date": "2026-03-02", "cohort_size": 1200, "d1_rate": 38.0, "d7_rate": 32.0, "d30_rate": 27.0}
        ],
        "total": 7
    }
}
```

### 2.4 漏斗转化查询

`business = "funnel"`，通过 `filters` 指定漏斗 ID 与转化窗口，`rows` 按步骤展开：

```json
{
    "business": "funnel",
    "timeRange": {
        "startTime": "2026-03-01 00:00:00",
        "endTime": "2026-03-07 23:59:59"
    },
    "granularity": "total",
    "metrics": [
        {"field": "step_users", "aggregation": "summary"},
        {"field": "conversion_rate", "aggregation": "avg"}
    ],
    "filters": [
        {"field": "funnel_id", "operator": "=", "value": "register_funnel"},
        {"field": "window_hours", "operator": "=", "value": 24}
    ]
}
```

**响应示例**:
```json
{
    "code": 0,
    "message": "success",
    "data": {
        "business": "funnel",
        "granularity": "total",
        "rows": [
            {"step": 1, "step_name": "访问注册页", "step_users": 10000, "conversion_rate": 100.0},
            {"step": 2, "step_name": "点击注册",   "step_users": 6000,  "conversion_rate": 60.0},
            {"step": 3, "step_name": "完成注册",   "step_users": 3000,  "conversion_rate": 50.0}
        ],
        "total": 3
    }
}
```

### 2.5 事件趋势查询

`business = "event"`，按天统计登录按钮点击次数与去重用户数：

```json
{
    "business": "event",
    "timeRange": {
        "startTime": "2026-03-01 00:00:00",
        "endTime": "2026-03-07 23:59:59"
    },
    "granularity": "day",
    "metrics": [
        {"field": "event_count", "aggregation": "count", "alias": "count"},
        {"field": "user_id", "aggregation": "distinct_count", "alias": "users"}
    ],
    "filters": [
        {"field": "event_name", "operator": "=", "value": "btn_login_click"}
    ]
}
```

**响应示例**:
```json
{
    "code": 0,
    "message": "success",
    "data": {
        "business": "event",
        "granularity": "day",
        "rows": [
            {"date": "2026-03-01", "count": 1200, "users": 800},
            {"date": "2026-03-02", "count": 1350, "users": 900}
        ],
        "total": 7
    }
}
```

### 2.6 事件属性分布

按登录方式（`login_type`）分组，统计各属性值的次数：

```json
{
    "business": "event",
    "timeRange": {
        "startTime": "2026-03-01 00:00:00",
        "endTime": "2026-03-07 23:59:59"
    },
    "granularity": "total",
    "dimensions": ["login_type"],
    "metrics": [
        {"field": "event_count", "aggregation": "count", "alias": "count"}
    ],
    "filters": [
        {"field": "event_name", "operator": "=", "value": "btn_login_click"}
    ]
}
```

**响应示例**:
```json
{
    "code": 0,
    "message": "success",
    "data": {
        "business": "event",
        "granularity": "total",
        "dimensions": ["login_type"],
        "rows": [
            {"login_type": "wechat",   "count": 800},
            {"login_type": "sms",      "count": 400},
            {"login_type": "password", "count": 133}
        ],
        "total": 3
    }
}
```


## 3. 响应规范

### 3.1 统一响应格式

```json
{
    "code": 0,
    "message": "success",
    "data": {}
}
```

### 3.2 错误码定义

| 错误码 | 含义 | HTTP 状态码 |
|--------|------|-------------|
| 0 | 成功 | 200 |
| 40001 | 参数错误 | 400 |
| 40002 | 日期范围超限 | 400 |
| 40101 | 未授权 | 401 |
| 40301 | 无权限访问 | 403 |
| 40401 | 事件不存在 | 404 |
| 50001 | 内部错误 | 500 |
| 50002 | 查询超时 | 504 |


## 4. 性能要求

| 接口类型 | 响应时间要求 | 说明 |
|----------|--------------|------|
| 事件趋势 | < 500ms | 预聚合数据 |
| 留存对比 | < 1s | 预聚合数据 |
| 漏斗分析 | < 1s | 预计算结果 |
| 同期群分析 | < 2s | 缓存加速 |
| 时间区间上限 | 366 天 | 超出返回 `40002` |
| dimensions 上限 | 3 个 | 超出返回 `40001` |
| metrics 上限 | 10 个 | 超出返回 `40001` |
| 响应行数上限 | 10,000 行 | 超出自动截断，响应标注 `truncated: true` |
