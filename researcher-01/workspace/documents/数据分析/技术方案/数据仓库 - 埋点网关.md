# 网关（Nginx 日志）

## 需求描述

使用 Nginx 作为埋点数据接入层，通过 access_log 记录埋点请求，经由 Filebeat 采集后交由 Logstash 解析处理并直写 MySQL ODS。

## 技术选型

| 方案 | 优点 | 缺点 | 选型 |
|------|------|------|------|
| Nginx + 日志采集 | 高性能、无需应用层处理、运维简单、成熟稳定 | 日志格式需规范化 | ✅ 推荐 |
| Go + Gin | 灵活可控、可实时处理 | 需独立部署维护 | - |
| Nginx + Lua | 与Nginx集成、可实时处理 | 维护成本高、生态有限 | ❌ 不适用 |

## Nginx 配置

```nginx
# /etc/nginx/nginx.conf

# 定义埋点日志格式
log_format tracking '$remote_addr - $remote_user [$time_local] '
                    '"$request" $status '
                    'req_id="$http_x_request_id" '
                    'device="$http_x_device_model" '
                    'os="$http_x_os_type" '
                    'os_ver="$http_x_os_version" '
                    'app_ver="$http_x_app_version_name" '
                    'network="$http_x_network_type" '
                    'tz="$http_x_time_zone" '
                    'lang="$http_accept_language" '
                    'device="$http_x_device_type" '
                    'channel="$http_x_distribution" '
                    'body="$request_body" '
                    'rt=$request_time';

server {
    listen 80;
    server_name analytics.moon-insight.com;

    # 埋点上报接口
    location /collect {
        # 记录埋点日志
        access_log /var/log/nginx/track.log tracking;
        access_log /var/log/nginx/track.json.log json_tracking;

        # 允许读取请求体
        client_body_buffer_size 1M;
        client_max_body_size 1M;

        # 快速返回 204，不阻塞客户端
        return 204;
    }

    # 批量上报接口
    location /batch/collect {
        access_log /var/log/nginx/track.log tracking;
        access_log /var/log/nginx/track.json.log json_tracking;

        client_body_buffer_size 5M;
        client_max_body_size 5M;

        return 204;
    }

    # 健康检查
    location /health {
        access_log off;
        return 200 "ok";
    }
}

# JSON 格式日志（便于 Filebeat 解析）
log_format json_tracking escape=json '{
    "@timestamp": "$time_iso8601",
    "remote_addr": "$remote_addr",
    "request_id": "$http_x_request_id",
    "device_model": "$http_x_device_model",
    "os_type": "$http_x_os_type",
    "os_version": "$http_x_os_version",
    "app_version": "$http_x_app_version_name",
    "app_version_code": "$http_x_app_version_code",
    "network_type": "$http_x_network_type",
    "timezone": "$http_x_time_zone",
    "language": "$http_accept_language",
    "device_type": "$http_x_device_type",
    "channel": "$http_x_distribution",
    "user_agent": "$http_user_agent",
    "body": "$request_body",
    "request_time": "$request_time"
}';
```

## Filebeat 配置

Filebeat 负责监听 Nginx 日志文件并转发到 Logstash，数据解析和转换交由 Logstash 处理。

```yaml
# /etc/filebeat/filebeat.yml

filebeat.inputs:
- type: log
  enabled: true
  paths:
    - /var/log/nginx/track.json.log

  # 多行合并（批量请求体可能跨行）
  multiline.pattern: '^\{'
  multiline.negate: true
  multiline.match: after

# 输出到 Logstash（由 Logstash 负责解析和写入 Redis Stream）
output.logstash:
  hosts: ["logstash:5044"]

# 监控
logging.level: info
monitoring.enabled: true
```

## Logstash 配置

```ruby
# /etc/logstash/conf.d/tracking.conf

input {
  beats {
    port => 5044
  }
}

filter {
  # 解析 Nginx JSON 日志
  json {
    source  => "message"
    target  => "nginx"
    remove_field => ["message"]
  }

  # 解析请求体中的埋点事件（JSON 字符串）
  json {
    source  => "[nginx][body]"
    target  => "event"
  }

  # IP 归属地 enrichment
  geoip {
    source => "[nginx][remote_addr]"
    target => "geoip"
    fields => ["city_name", "country_code2", "region_name", "location"]
  }

  # User-Agent 解析
  useragent {
    source => "[nginx][user_agent]"
    target => "ua"
  }

  # 字段标准化
  mutate {
    rename => {
      "[event][user_id]"    => "user_id"
      "[event][device_id]"  => "device_id"
      "[event][event_name]" => "event_name"
      "[event][event_time]" => "event_time"
      "[event][page_path]"  => "page_path"
      "[event][platform]"   => "platform"
      "[nginx][app_version]" => "app_version"
      "[nginx][channel]"    => "channel"
    }
    # 敏感字段脱敏
    gsub => ["[event][phone]", "(?<=\d{3})\d{4}(?=\d{4})", "****"]
  }

  # 统一时间戳
  date {
    match => ["event_time", "UNIX_MS", "ISO8601"]
    target => "@timestamp"
  }

  # 移除多余字段
  mutate {
    remove_field => ["nginx", "agent", "log", "input", "ecs", "host", "tags"]
  }
}

output {
  # 直写 MySQL ODS 层（需安装 logstash-output-jdbc 插件）
  jdbc {
    driver_class       => "com.mysql.cj.jdbc.Driver"
    driver_jar_path    => "/usr/share/logstash/drivers/mysql-connector-j-8.0.33.jar"
    connection_string  => "jdbc:mysql://mysql:3306/dwh_ods?useSSL=false&serverTimezone=Asia/Shanghai"
    username           => "logstash"
    password           => "${MYSQL_PASSWORD}"
    statement          => [
      "INSERT INTO ods_tracking_event_raw (user_id, device_id, event_name, event_time, page_path, platform, app_version, channel, ip, country, city, ua_os, ua_browser, properties, created_at) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, NOW())",
      "%{user_id}", "%{device_id}", "%{event_name}", "%{event_time}",
      "%{page_path}", "%{platform}", "%{app_version}", "%{channel}",
      "%{[nginx][remote_addr]}", "%{[geoip][country_code2]}", "%{[geoip][city_name]}",
      "%{[ua][os]}", "%{[ua][name]}", "%{[event][properties]}"
    ]
  }

  # 写入 Redis 用于实时指标计数（PV/UV 等）
  redis {
    host      => "redis"
    port      => 6379
    key       => "track:realtime:events"
    data_type => "list"
  }
}
```

## 日志轮转配置

```bash
# /etc/logrotate.d/nginx-tracking
/var/log/nginx/track*.log {
    daily
    rotate 7
    missingok
    compress
    delaycompress
    notifempty
    create 644 nginx nginx
    sharedscripts
    postrotate
        /bin/kill -USR1 $(cat /var/run/nginx.pid 2>/dev/null) 2>/dev/null || true
    endscript
}
```

## 部署架构

```yaml
# docker-compose.yml
version: '3'
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - ./logs:/var/log/nginx
    logging:
      driver: json-file
      options:
        max-size: "100m"
        max-file: "3"

  filebeat:
    image: docker.elastic.co/beats/filebeat:8.11.0
    volumes:
      - ./logs:/var/log/nginx:ro
      - ./filebeat.yml:/usr/share/filebeat/filebeat.yml:ro
    user: root
    depends_on:
      - nginx
      - logstash

  logstash:
    image: docker.elastic.co/logstash/logstash:8.11.0
    ports:
      - "5044:5044"   # Beats 输入
    volumes:
      - ./logstash/tracking.conf:/usr/share/logstash/pipeline/tracking.conf:ro
      - ./logstash/GeoLite2-City.mmdb:/usr/share/logstash/GeoLite2-City.mmdb:ro
    environment:
      - "LS_JAVA_OPTS=-Xmx512m -Xms512m"
    depends_on:
      - nginx
```

## 方案优势

1. **高性能**: Nginx 处理静态返回，无业务逻辑，单机可达 10万+ QPS
2. **简单稳定**: 无需维护应用代码，Nginx 成熟稳定
3. **数据可靠**: 日志落盘后异步采集，不丢数据
4. **强大的数据处理**: Logstash 提供 GeoIP、UA 解析、字段映射、脱敏等丰富 Filter
5. **解耦清晰**: Filebeat 只负责日志传输，Logstash 负责解析转换，职责分离

## 注意事项

1. **磁盘空间**: 埋点日志量大，需配置合理的日志轮转策略
2. **实时性**: 日志采集 + Logstash 处理有秒级延迟，不适合强实时场景
3. **Logstash 内存**: 默认 JVM 堆较大，建议配置 `-Xmx512m` 控制内存占用
4. **GeoIP 库**: 需定期更新 GeoLite2-City.mmdb 以保证 IP 归属地准确性
5. **敏感数据**: 通过 Logstash mutate filter 在入队前完成脱敏
