# 数据采集

## 1. 背景与目标

### 1.1 问题背景

当前用户中心积累了大量业务数据（用户注册、登录、资料变更等），但缺乏统一的数据采集机制。业务数据分散在各系统中，存在以下问题：
- 业务数据库查询影响线上性能
- 业务数据分散，无法跨系统关联分析
- 缺乏实时数据通道，无法支持实时分析
- 数据质量无法保证

### 1.2 目标

- **业务目标**: 建立统一的数据采集通道，确保数据完整、及时、准确
- **产品目标**: 支持日志采集、CDC 数据同步、实时数据清洗
- **技术目标**: 实现秒级数据采集延迟，支持亿级数据量

### 1.3 成功指标

| 指标 | 当前值 | 目标值 | 测量方式 |
|------|--------|--------|----------|
| 采集延迟 | - | < 1 分钟 | 数据入 MySQL ODS 时间监控 |
| 数据完整性 | - | > 99.9% | 数据对账监控 |
| 采集成功率 | - | > 99.5% | 失败重试监控 |


## 2. 约束条件

### 2.1 隐私合规

- 首次启动需获取用户同意（隐私协议）
- 支持用户关闭数据采集（opt-out）
- 敏感字段脱敏（手机号、身份证号等）
- 支持数据删除请求（被遗忘权）

### 2.2 技术约束

- 日志采集基于 Filebeat，数据解析与转换基于 Logstash（直写 MySQL ODS），CDC 基于 Debezium/Canal
- 实时指标由 Logstash 直写 Redis，批处理 ETL 使用 Flink（读 MySQL ODS）
- 不得影响业务数据库线上性能


## 3. 功能需求

### 3.1 功能清单

| 编号 | 功能点 | 优先级 | 依赖 |
|------|--------|--------|------|
| F1 | 系统日志采集（Filebeat） | P0 | - |
| F2 | 数据清洗与转换（ETL） | P0 | F1 |
| F6 | 数据质量监控 | P1 | F1 |
| F8 | 实时数据看板 | P2 | F2 |

### 3.2 详细设计

#### 功能 F1: 系统日志采集

**需求描述**: 实现系统日志的实时采集，支持应用日志、错误日志、接口日志等。

**数据来源**:

| 数据源 | 采集方式 | 频率 | 说明 |
|--------|---------|------|------|
| 系统日志 | Filebeat → Logstash → MySQL ODS | 实时 | 应用日志、错误日志、接口日志；Logstash 负责解析、GeoIP、脱敏 |
| 业务数据库 | Canal → Logstash → MySQL ODS | 实时 | 用户表、登录记录等变更 |

**技术方案**: 详见 [数据仓库 - 埋点网关](../../../技术文档/数据仓库/技术方案/数据仓库%20-%20埋点网关.md) 及 [数据仓库 - 整体设计](../../../技术文档/数据仓库/数据仓库%20-%20整体设计.md)。

#### 功能 F2: 数据清洗与转换

**需求描述**: 对采集的原始数据进行清洗、转换、脱敏，构建标准化数据格式。

**清洗规则**:

| 规则 | 说明 | 示例 |
|------|------|------|
| 字段映射 | 字段名标准化 | user_name → username |
| 数据脱敏 | 敏感字段加密 | phone: 138****8888 |
| 格式校验 | 数据类型检查 | 日期格式校验 |
| 异常过滤 | 剔除异常数据 | 明显错误的 IP 地址 |
| 数据去重 | 重复数据剔除 | 基于主键去重 |
| 时区转换 | 统一时区 | UTC → Asia/Shanghai |

**技术方案**: 详见 [数据仓库 - 实时流计算方案](../../../技术文档/数据仓库/技术方案/数据仓库%20-%20实时流计算方案.md)。

#### 功能 F6: 数据质量监控

**需求描述**: 监控数据采集质量，及时发现异常并告警。

**监控指标**:

| 指标 | 阈值 | 告警方式 |
|------|------|---------|
| 采集延迟 | > 5 分钟 | 钉钉告警 |
| 采集失败率 | > 1% | 钉钉告警 |
| 数据完整性 | < 99% | 邮件告警 |
| 异常数据比例 | > 5% | 邮件告警 |

#### 功能 F8: 实时数据看板

**需求描述**: 展示数据采集的实时状态和指标。

**展示内容**:

| 指标 | 说明 |
|------|------|
| 实时采集速率 | 条/秒 |
| 各数据源状态 | 正常/异常 |
| 数据延迟分布 | P50/P99 延迟 |
| 数据质量评分 | 综合质量分数 |
| 异常告警列表 | 最近告警 |


## 4. 数据流架构

整体采集架构详见 [数据仓库 - 整体设计](../../../技术文档/数据仓库/数据仓库%20-%20整体设计.md)。

```
业务系统日志 → Filebeat → Logstash（解析/GeoIP/脱敏）→ MySQL ODS → Flink（批处理 ETL）→ DWD/DWS/ADS
业务数据库   → Canal → Logstash                       → MySQL ODS → Flink（批处理 ETL）→ DWD/DWS/ADS
前端SDK      → 埋点网关(Nginx) → Filebeat → Logstash  → MySQL ODS → Flink（批处理 ETL）→ DWD/DWS/ADS
                                                       └→ Redis（实时指标 PV/UV）
```


## 5. 非功能需求

### 5.1 性能指标

|------|--------|

| 数据清洗延迟 | < 30 秒 |
| 单节点吞吐量 | > 10 万条/秒 |

### 5.2 可靠性

| 指标 | 目标值 |
|------|--------|
