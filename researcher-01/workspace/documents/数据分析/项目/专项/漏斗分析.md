# 漏斗分析

## 1. 背景与目标

### 1.1 问题背景

当前产品缺乏对关键业务流程转化效果的系统性分析，无法准确定位用户在哪个环节流失，导致转化率优化缺乏数据支撑。

### 1.2 目标

- 建立标准化的漏斗分析体系，支持任意业务流程的转化分析
- 支持灵活配置多步骤漏斗，满足不同业务场景需求
- 支持按多维度（渠道、平台、版本）下钻分析转化差异
- 支持转化窗口期自定义，适应不同业务周期
- 支持漏斗对比分析，评估优化效果

## 2. 指标定义

### 2.1 漏斗类型

| 漏斗类型 | 说明 | 适用场景 |
|----------|------|----------|
| **有序漏斗** | 用户必须按顺序完成各步骤 | 注册流程、下单流程等严格顺序业务 |
| **无序漏斗** | 用户只需完成各步骤，顺序不限 | 功能使用、多入口转化等场景 |

### 2.2 核心指标

| 指标名称 | 定义 | 计算口径 |
|----------|------|----------|
| **步骤转化人数** | 完成该步骤的用户数 | 去重统计触发该事件的用户数 |
| **步骤转化率** | 当前步骤人数 / 上一步骤人数 × 100% | 相邻步骤间的转化比例 |
| **整体转化率** | 最后一步人数 / 第一步人数 × 100% | 漏斗起点到终点的转化比例 |
| **流失率** | 100% - 步骤转化率 | 该步骤的流失比例 |
| **流失人数** | 上一步人数 - 当前步人数 | 该步骤流失的用户数 |

### 2.3 计算示例

```
注册转化漏斗示例：

步骤1: 进入注册页 - 100,000人
步骤2: 输入手机号 - 60,000人 (转化率 60%, 流失 40,000人)
步骤3: 发送验证码 - 45,000人 (转化率 75%, 流失 15,000人)
步骤4: 验证通过   - 40,000人 (转化率 88.9%, 流失 5,000人)
步骤5: 注册成功   - 35,000人 (转化率 87.5%, 流失 5,000人)

整体转化率 = 35,000 / 100,000 × 100% = 35%
```

### 2.4 特殊说明

| 场景 | 处理方式 |
|------|----------|
| **重复触发** | 同一用户在窗口期内多次触发同一事件，只计为1次 |
| **多设备触发** | 同一用户在多设备分别触发，按设备维度独立计算 |
| **超出窗口期** | 超出设定时间窗口的步骤触发，不计入该漏斗 |
| **漏斗重入** | 用户完成漏斗后再次进入，视为新的漏斗实例 |

## 4. 埋点事件设计

### 4.1 标准漏斗事件

| 事件名 | 事件显示名 | 触发时机 | 使用场景 |
|--------|-----------|----------|----------|
| **register_page_view** | 注册页浏览 | 用户进入注册页面时 | 注册漏斗起点 |
| **phone_input** | 输入手机号 | 用户输入手机号完成时 | 注册漏斗步骤 |
| **code_sent** | 验证码发送 | 点击发送验证码成功时 | 注册漏斗步骤 |
| **code_verified** | 验证码验证 | 验证码验证成功时 | 注册漏斗步骤 |
| **register_success** | 注册成功 | 用户注册成功时 | 注册漏斗终点 |
| **home_page_view** | 首页浏览 | 用户进入首页时 | 电商漏斗起点 |
| **product_detail_view** | 商品详情页 | 进入商品详情页时 | 电商漏斗步骤 |
| **add_to_cart** | 加入购物车 | 商品加入购物车时 | 电商漏斗步骤 |
| **order_submit** | 提交订单 | 点击提交订单时 | 电商漏斗步骤 |
| **payment_success** | 支付成功 | 订单支付成功时 | 电商漏斗终点 |

### 4.2 事件上下文定义

**漏斗相关事件通用上下文**

| 属性名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| `context.funnel_id` | string | 所属漏斗标识 | "funnel_register_001" |
| `context.step_order` | int | 步骤序号 | 1, 2, 3... |
| `context.source_channel` | string | 来源渠道 | "AppStore", "wechat_ads" |
| `context.referrer_page` | string | 来源页面 | "/home", "/promo/spring" |

### 4.3 埋点协议

> **详细埋点协议**（HTTP Header、请求体格式、API接口、SDK实现、设备ID方案等）请参考：

### 4.4 采集策略

| 事件类型 | 上报策略 | 说明 |
|----------|----------|------|
| 漏斗步骤事件 | **实时上报** | 立即发送，失败则重试3次 |
| 批量漏斗事件 | **延迟上报** | 10秒内批量上报，减少网络请求 |

## 6. 报表设计

### 6.1 漏斗转化报表

| 项目 | 内容 |
|------|------|
| **功能** | 展示指定漏斗各步骤的转化情况 |
| **维度** | 日期、漏斗名称 |
| **指标** | 各步骤用户数、步骤转化率、整体转化率、流失人数 |
| **图表类型** | 漏斗图、柱状图 |

### 6.2 漏斗趋势报表

| 项目 | 内容 |
|------|------|
| **功能** | 展示漏斗转化率随时间变化趋势 |
| **维度** | 日期 |
| **指标** | 整体转化率、各步骤转化率 |
| **图表类型** | 折线图 |

### 6.3 漏斗对比报表

| 项目 | 内容 |
|------|------|
| **功能** | 对比不同维度的漏斗转化表现 |
| **维度** | 渠道、平台、版本、漏斗类型 |
| **指标** | 各维度转化率、流失率 |
| **图表类型** | 分组柱状图、对比漏斗图 |

### 6.4 流失分析报表

| 项目 | 内容 |
|------|------|
| **功能** | 分析用户在哪个步骤流失，以及流失后的行为 |
| **维度** | 漏斗步骤 |
| **指标** | 流失人数、流失率、流失后流向 |
| **图表类型** | 桑基图、流向图 |

### 术语表

| 术语 | 说明 |
|------|------|
| 漏斗 | 描述用户完成一系列步骤的转化过程 |
| 有序漏斗 | 用户必须按既定顺序完成各步骤的漏斗 |
| 无序漏斗 | 用户只需完成各步骤，顺序不限的漏斗 |
| 转化窗口期 | 用户完成漏斗所有步骤的最大时间间隔 |
| 步骤转化率 | 当前步骤用户数占上一步骤用户数的比例 |
| 整体转化率 | 完成漏斗的用户数占进入漏斗用户数的比例 |
